# Requirements

These are repository-level requirements shared by every utility in the collection. Individual utilities add their own requirements and design documents under `memory-bank/design/`.

## Functional Requirements

1. The repository hosts multiple small, self-contained utility projects (containers, jigs, fixtures, and similar), each as its own directory under `src/`.
2. Each utility is defined in Python with build123d and exports its geometry as a STEP file into `manufacture/`.
3. Each utility's dimensions are expressed as Python parameters (variables or function arguments) rather than hard-coded literals, so the object can be regenerated by re-running its module.
4. Generated STEP files are written to `manufacture/` and are not committed to version control.

## Non-Functional Requirements

1. Models use millimeters as the unit of length.
2. Models manufacture cleanly on at least one of an FDM 3D printer or a subtractive mill; designs state which method(s) they target.
3. Machine-screw features follow the dimensions in `resources/modeling/screws.md`; mill-bed jigs follow `resources/modeling/vertical_mill_jigs.md`.

## Constraints

1. The only third-party dependencies are build123d, pytest, and ocp_vscode, as declared in `pyproject.toml`.
2. The source of truth for any object is its Python module, not a STEP file or a CAD session.
3. Reusable knowledge belongs under `resources/`; per-utility design notes belong under `memory-bank/design/`.
